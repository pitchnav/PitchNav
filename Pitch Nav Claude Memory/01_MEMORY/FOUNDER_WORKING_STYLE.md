# Founder Working Style

## Communication

Luke prefers:

- Exact, easy-to-follow steps
- Simple explanations of technical concepts
- Clear instructions about what to open, click, paste, or run
- One contained task at a time
- A visible checkpoint before moving forward
- Honest statements when something is unknown
- Working examples rather than abstract explanations

Avoid:

- Giant unexplained code dumps
- Ten simultaneous next steps
- Vague instructions such as “configure the integration”
- Assuming Luke knows where folders, terminals, repositories, or settings are
- Repeating technical jargon without translating it
- Telling Luke a task is complete when it has not been tested

## Development workflow

- Codex has previously felt easier and more aligned with Luke’s intent than Claude.
- Claude Code should earn trust by working in small steps and showing verification.
- Never make broad rewrites before inspecting the current code.
- Always preserve a working backup or Git branch.
- Prefer development and test data.
- Give one manual verification action after a meaningful change.

## Design preferences

- Premium startup quality
- Dark, modern, technical visual system
- Professional and realistic
- Smooth animation
- Mobile version is required
- Simple wording for athletes
- Avoid cartoon or obviously generated-looking visual elements
