# Memory Update Protocol

## Step 1 — Capture

Put new potentially durable information in [[01_MEMORY/MEMORY_INBOX]].

## Step 2 — Classify

Classify it as:

- Confirmed fact
- Approved decision
- Founder preference
- Current priority
- Hypothesis
- Draft idea
- Unknown
- Superseded information

## Step 3 — Verify

Use one or more of:

- Founder confirmation
- Actual code
- Database schema
- Product behavior
- Approved document
- Reliable external source

## Step 4 — Update

Update the narrowest relevant canonical note. Add:

- Date
- Source
- Status
- Any limitation

## Step 5 — Preserve history

When a fact or decision changes:

- Mark the old entry superseded
- Link to the replacement
- Do not erase the old history

## Step 6 — Refresh active context

When priorities change, update [[01_MEMORY/CURRENT_FOCUS]].

## Step 7 — Handoff

After a meaningful session, update [[09_SESSIONS/SESSION_HANDOFF]].

## Token discipline

Do not keep expanding the always-loaded files. Move detailed information into topic notes and keep the core memory concise.
